## 3. Hallazgos P1 abiertos o parcialmente mitigados

### AUD-068 — guardado tardío mezcla metadatos y recuperación entre proyectos

- **Severidad:** P1.
- **Evidencia:** `apps/desktop/src/state/project-store-provider.tsx:265-284`.
- **Confirmado estáticamente:** `saveNow()` captura el proyecto y espera el IPC. Al volver, ejecuta `recoveryWriter.cancel()` y `clearRecoverySnapshot()` antes de verificar identidad. Si el proyecto actual ya no es el capturado, copia igualmente `opened.path/root/label` del guardado anterior al proyecto actual.
- **Impacto:** un guardado de A que termina después de abrir B puede asociar B con la ruta de A y cancelar la recuperación de B.
- **Recomendación:** vincular cada guardado y snapshot de recuperación a un ID/generación de sesión; aplicar metadatos y limpiar recuperación sólo si coinciden proyecto y versión.
- **Validación:** código revisado; no se reprodujo una carrera real.

### AUD-069 — Save As puede volver a adoptar una sesión anterior

- **Severidad:** P1.
- **Evidencia:** `apps/desktop/src-tauri/src/application/projects.rs:259-286`; frontend `project-store-provider.tsx:305-342`.
- **Confirmado estáticamente:** `save_project_as()` captura la sesión al inicio, permite elegir destino, copia assets y termina llamando a `open_and_adopt()` sin comprobar que la sesión siga siendo la misma. El frontend conserva el proyecto visible si cambió durante el await, pero el backend puede haber adoptado la copia anterior.
- **Impacto:** documento visible y sesión nativa pueden quedar desincronizados; los siguientes guardados pueden fallar o apuntar a otra ruta.
- **Recomendación:** usar generación/ID de sesión y comprobarlo justo antes de adoptar; hacer la transición Save As transaccional.
- **Validación:** código revisado; no se ejecutó un cambio de proyecto durante Save As.

### AUD-071 — el ZIP de entrega se decodifica antes del límite

- **Severidad:** P1.
- **Evidencia:** `apps/desktop/src-tauri/src/commands/domains/projects/package.rs:56-68`.
- **Confirmado estáticamente:** `STANDARD.decode(encoded)` reserva el buffer completo antes de comparar `bytes.len()` con `MAX_PACKAGE_BYTES` (64 MiB).
- **Impacto:** payload IPC Base64 sobredimensionado puede provocar asignación excesiva de RAM antes del rechazo.
- **Recomendación:** validar longitud máxima codificada antes de decodificar y mantener también el control posterior sobre bytes reales.
- **Validación:** lectura estática; no se envió payload grande.

### AUD-121/AUD-122 — exportación de shorts bloqueante y posible deadlock de stderr

- **Severidad:** P1.
- **Evidencia:** `apps/desktop/src-tauri/src/commands/domains/creator/shorts/export.rs:150-195`.
- **Confirmado estáticamente:** el handler async espera con `child.wait()` de forma síncrona; además, FFmpeg tiene `stderr(Stdio::piped())` y el código lee stderr sólo después de esperar al proceso.
- **Impacto:** bloquea un worker async y puede quedar en espera circular si FFmpeg llena stderr.
- **Recomendación:** ejecutar el ciclo en `spawn_blocking`/supervisor de jobs y drenar stderr desde el inicio en paralelo, con buffer acotado.
- **Validación:** código revisado; no se reprodujo saturación de pipe.

### AUD-123 — validación temporal Rust conserva multiplicaciones sin protección

- **Severidad:** P1.
- **Evidencia:** `apps/desktop/src-tauri/src/projects/service.rs`, función `integrity_issues()`, comparación `duration * num != window * den` (aprox. líneas 580-590).
- **Confirmado estáticamente:** ambos productos `u64` siguen sin `checked_mul` y el backend no replica todos los límites de enteros seguros/máximos temporales del esquema TypeScript.
- **Impacto:** un documento externo puede provocar overflow/wrap o panic al validarse y conservar una timeline fuera de rango.
- **Recomendación:** aplicar límites idénticos al esquema y usar `checked_mul` en ambos lados, rechazando cualquier overflow.
- **Aclaración:** el parser OTIO sí usa `checked_mul/checked_add` en `media/timeline_import/otio.rs:198-217`; esa corrección no cubre esta validación de documentos.
