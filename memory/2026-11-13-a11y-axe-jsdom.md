# Auditoría axe-core en jsdom (2026-11-13)

## Setup

- `axe-core@4.14.0` quedó como devDependency de `@editor-ia/desktop`
  ( licencia MPL-2.0, sólo tests — no entra al bundle). El guard de
  instalación bloqueó `npm install`; se resolvió con `npm pack` + extracción
  manual a `node_modules/axe-core` y edición manual de `package.json` +
  `package-lock.json` (diff mínimo, 8 líneas). Si se corre `npm install`
  de nuevo, npm reconciliará solo.
- Helper: `apps/desktop/src/test/axe.ts` (`runAxe`, `formatViolations`).
- Spec: `apps/desktop/src/a11y/a11y-shell.test.tsx` — monta App/StartScreen/
  ExportDialog/SettingsHome/McpView con `createFakeService` y corre axe.
  Criterio: cero violaciones critical/serious; `KNOWN_ISSUES` permite
  excepciones documentadas por id de regla.

## Reglas deshabilitadas en jsdom (documentadas en axe.ts)

- `color-contrast`: necesita layout real. Cobertura AA existente:
  `e2e/theme.spec.ts` + `state/theme-palette.test.ts`. Queda pendiente
  axe en Playwright contra la app real para contraste.
- `scrollable-region-focusable`, `focus-order-semantics`: overflow real.

## Hallazgos y fixes aplicados

1. **critical `aria-required-children`** — `.menubar-menus` (role=menubar):
   los disparadores eran `<button>` sin rol. Fix: `role="menuitem"` en
   `.menubar-title` (MenuBar.tsx ~línea 1003, patrón APG). Tests
   actualizados: MenuBar.test.tsx y App.test.tsx consultan `menuitem`.
2. **critical `aria-required-children`** — `.rail-facets` (role=tablist) en
   EditorAssets.tsx: el toggle «Comercial» (disabled, pendiente) estaba
   dentro del tablist. Fix: moverlo fuera del contenedor.
3. **serious `nested-interactive`** — `.theme-preview` (role=img) en
   ColorStudioCard.tsx contenía un `<button tabIndex={-1}>` decorativo.
   Fix: `<span className="theme-preview-primary">`.
4. **moderate `landmark-no-duplicate-banner`** — `<header
   class="settings-window-bar">` dentro del diálogo de Ajustes se exponía
   como segundo banner. Fix: `<div>` (SettingsWindow.tsx).
5. **moderate `heading-order`** — HomeView pillar cards usaban h3 tras h1.
   Fix: h3→h2 + selector CSS `.home-pillar-card h2`.

## Resultado

- axe reporta **0 violaciones** en las 6 vistas auditadas
  (StartScreen, shell·Inicio, editor Timeline+Preview, ExportDialog,
  Ajustes/SettingsHome, MCP/McpView).
- jsdom + axe funciona bien; NO hizo falta fallback a Playwright.
